# Python 解释器、环境与运行命令

## 一句话结论

IDE 显示已安装解释器，不等于当前运行命令一定能找到它；实际执行取决于运行器调用的命令、PATH 和项目所选环境。

## 直觉解释

终端或 IDE 运行 Python 时，至少涉及三件事：

1. 运行器最终执行了哪个命令，例如 `python`、`python3` 或某个环境中的绝对路径；
2. 当前 PATH 能否找到这个命令；
3. 找到的解释器是否属于当前项目期望的虚拟环境。

`command not found`（常见退出码 127）说明 shell 没找到那个命令名，不等于机器完全没有 Python。

## `venv`、`.venv` 与 conda

- `venv` 是 Python 标准库中的虚拟环境创建工具。
- `.venv` 只是项目内常用的虚拟环境目录名，不是另一种环境管理工具，也不是一个单独的“环境文件”。
- conda 是跨语言的包与环境管理器，可以管理 Python 解释器和非 Python 依赖；它不是“Python 2.7 以上默认环境工具”，也不是 `.venv` 文件。
- 项目通常在 `venv`/`.venv` 与 conda 中选择一种主环境方案，避免同一项目混用造成解释器和依赖来源不清。

## 本次故障闭环

- 现象：终端使用 `python3` 能运行，Trae Run Code 使用 `python` 时报告 command not found。
- 原因：运行器调用的命令名与当时 PATH 中可用命令不一致。
- 修复证据：用户调整后，`python -u hello.py` 能实际输出结果。
- 更正：不能笼统说“所有 Python 都不叫 `python`”；是否存在裸命令 `python` 只取决于当前环境和 PATH。

## 推荐的项目运行判断

1. 确认项目选中的解释器路径。
2. 在同一运行环境中检查 Python 版本。
3. 使用项目入口运行，而不是只测试单个编辑器按钮。
4. 确认依赖来自项目环境。
5. 以真实输出、退出码和测试结果判断成功。

## 与 AI Agent 工程的关联

Agent 项目常同时包含 FastAPI、Pydantic、模型 SDK 和本地服务。解释器或依赖环境混乱会表现为模块缺失、版本不兼容、调用行为不同，因此环境路径也是排错证据的一部分。
