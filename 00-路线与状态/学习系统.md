# 指令驱动的学习系统

这套系统把仓库从静态目录升级为可重复执行的学习闭环。持久的是 Markdown、状态文件和 Git 历史，不是某个 Chat Session 或常驻 Agent。

## 设计来源

### Karpathy LLM Wiki 映射

| LLM Wiki 角色 | 本仓库实现 |
|---|---|
| Raw | `01-输入区/` 及用户在其他区域写下的原始内容；不得被整理操作覆盖 |
| Wiki | `03-整理区/` 的稳定知识、`07-总结与评估/` 的综合结论及它们之间的链接 |
| Schema | `AGENTS.md`、本页、配置文件和模板 |
| Ingest | 识别新增内容，保留来源，更新已有知识或创建新知识页 |
| Query | 回答学习问题，并在同一轮保存问题原文与 Agent 完整回答；后续再提炼稳定知识与链接 |
| Lint | 检查未处理输入、孤岛、重复、冲突、断链、失效来源和复习状态 |

关键不是创建更多文件，而是让新输入更新旧理解，让旧知识进入后续提问、练习、项目和复习。

## 学习问答强制留痕

用户在学习过程中提出问题时，发问本身即授权本轮问答落库，不需要附加“记录”指令：

1. 已确定当前 Day：追加到对应 `02-每日笔记/Day-N/学习记录.md` 的“问题与 Agent 回答”。
2. 未确定当前 Day：追加到 `01-输入区/问题与回答/YYYY-MM-DD.md`，作为待摄入原始记录。
3. 保存用户问题原文和 Agent 实际交付的完整回答，并记录时间、主题和待验证/已确认状态。
4. 后续发现回答错误时不覆盖旧回答，而是追加更正、依据和影响范围。
5. 问答记录不自动代表用户已经掌握；只有真实复述、练习或实验才能更新掌握状态。
6. 敏感信息必须脱敏，不得把密钥、Token、密码或私钥写入仓库。

### 学习机制

- **主动回忆**：复习时先回答问题，之后才能查看答案和解析。
- **间隔复习**：默认使用 `1 → 3 → 7 → 14 → 30` 天间隔，不是每天重复阅读。
- **表现自适应**：`again / hard / good / easy` 会改变阶段和下次日期。
- **生成与预测**：代码运行前先预测输出；项目问题先提出判断再验证。
- **交错练习**：同一天到期的卡片可跨 Python、LLM、RAG、Agent 混合出现。
- **可追溯**：每个复习项必须链接到原始笔记、整理页或实验。
- **负荷受控**：默认每日复习预算 25 分钟；超过预算的到期项保留原日期，下一次继续参与排序。

默认间隔是透明、低成本的起点，不宣称是适用于所有人的固定“记忆曲线”。实际表现会改变排期。

## 复习负荷与优先级

系统按每张卡片约 2 分钟估算负荷，默认每天最多安排 25 分钟。预算只限制当天展示数量，不改变事实源中的到期日期。未进入今日任务的卡片会列在“超出今日预算”区，仍是到期或逾期状态。

卡片优先级由 Agent 在创建时根据用途判断，必须能追溯到当天内容：

| 优先级 | 含义 | 典型内容 |
|---:|---|---|
| 3 | 求职/项目关键 | Agent 调用链、RAG 证据、评测、故障定位、架构取舍 |
| 2 | 当前阶段核心 | Python/LLM 基础中会直接阻塞后续实践的知识 |
| 1 | 补充 | 可随时查阅、遗忘后不会阻塞当前任务的辅助知识 |

到期卡片依次按“优先级更高 → 历史失败更多 → 逾期更久 → 阶段更低”排序。同级时用卡片 ID 保持结果稳定。Agent不得为了清空数字把超预算项手工改期。

## 两个状态机

### 内容状态

```text
未处理输入
→ 已摄入
→ 稳定知识 / 练习 / 项目证据 / 仅保留原始记录
→ 建立关联
→ 进入后续查询与复习
```

### 复习状态

```text
新卡片
→ D+1 到期
→ 回答与评级
→ D+3 / D+7 / D+14 / D+30 再次到期
→ 多轮稳定回忆
→ 已掌握归档
```

答错或依赖大量提示会缩短间隔。归档不是“看过一次”，而是至少完成五轮复习，并在最高阶段保持连续稳定表现。

## 任意区域输入如何处理

用户可以在 `01-输入区/`、每日笔记、整理区、练习区、项目区或总结区直接写内容。复习索引、队列、卡片和已掌握目录由状态机管理，不作为普通 Ingest 输入。收到处理指令后：

1. 运行 `python3 scripts/learning_ops.py scan`，识别相对上次处理后新增、修改或删除的学习文件。
2. 判断文件所在位置是否已经合理。
3. 位置合理：保留原位，只做整理、链接和索引更新。
4. 原始材料或临时记录放错位置：原文不覆盖；必要时迁入输入区，或在正确目录创建派生页并链接来源。
5. 优先更新已有稳定知识页，避免同一概念每天新建一页。
6. 不确定分类、事实冲突或移动会改变用户组织方式时，停止并询问。
7. 全部处理完成后运行 `checkpoint`，记录本轮文件指纹；下一次不会重复处理未变化内容。

`scan` 是范围发现工具，不代表 Agent 可以无条件改写扫描结果。

## 核心指令

### `执行今日学习收尾 Day N`

这是唯一默认授权多个连续动作的复合指令：

1. 扫描本轮新增和修改内容。
2. 执行 Ingest：归位、整理、补充、链接和去重。
3. 更新当天总结与真实学习进度。
4. 从当天内容中选择值得长期记忆的原子知识，创建复习卡片。
5. 注册卡片并生成当日到期复习队列。
6. 执行学习系统 Lint。
7. 更新处理游标并输出收尾报告。

该指令不授权：替用户完成复习、自动调整下一天、commit、push、修改 AtlasOps 或求职资产。

### `整理未归档输入`

只执行扫描、Ingest、索引更新、Lint 和 checkpoint；不更新当天完成度，不创建练习题。

### `生成今日复习任务`

根据日期、每日预算和优先顺序把到期项写入 `06-复习区/今日复习/YYYY-MM-DD.md`，并在同页列出未入选的仍到期项。这一步不展示答案，也不代表已经复习。

### `开始今日复习`

按今日队列一次展示一个问题。用户回答前不得读取或展示卡片答案。Agent记录回答、正确性、提示程度和信心，但尚不重排期。

### `完成今日复习并重新排期`

Agent根据真实表现逐项使用：

| 等级 | 判定 |
|---|---|
| `again` | 核心答案错误、无法回忆，或答案来自直接查看资料 |
| `hard` | 部分正确但依赖明显提示，关键解释或应用仍不稳定 |
| `good` | 不看资料能正确回答并说明原因 |
| `easy` | 能正确回答、对比、应用，并处理一个变体或反例 |

脚本计算下一日期；达到归档条件时把卡片移动至 `06-复习区/已掌握/`。一次复习不会触发归档。

### `检查学习系统`

检查：未处理文件、无来源整理页、重复卡片、丢失卡片、无效日期、孤立知识、冲突和逾期项。只报告或修复机械问题；涉及内容取舍时询问用户。

## 确定性工具

```bash
python3 scripts/learning_ops.py scan
python3 scripts/learning_ops.py checkpoint
python3 scripts/learning_ops.py next-id
python3 scripts/learning_ops.py register --id K0001 --card "06-复习区/知识卡片/K0001-example.md" --created 2026-08-20 --priority 3
python3 scripts/learning_ops.py due --date 2026-08-21 --write
python3 scripts/learning_ops.py record --id K0001 --rating good --date 2026-08-21 --confidence 4
python3 scripts/learning_ops.py lint
```

Agent不得手算日期后直接覆盖复习索引；必须通过工具或在工具不可用时明确报告阻塞。

## 不进入复习系统的内容

- 可以随时查文档的低价值细节；
- 没有证据支持的临时推测；
- 一次性命令、路径和环境噪音；
- 已被更稳定概念包含的重复卡片；
- 只需要理解、不值得逐字记忆的长段文字。

优先建立能帮助代码阅读、故障判断、架构解释和面试防守的卡片。

## Day 3 / Day 7 累积口述验收

每日 3–5 分钟复述检查当天知识，累积口述则检查能否把多天知识连接成完整工程链路：

- Day 3：5–7 分钟，讲清 Python API、LLM 请求、结构化输出、校验和失败处理的端到端链路。
- Day 7：10–15 分钟，讲清 Agent/RAG/工作流的系统边界、证据、评测、安全和生产约束，并映射到 AtlasOps。

评分、通过条件和记录格式见 [`累积口述验收.md`](累积口述验收.md)。只有用户完成真实口述或提供逐字稿后才评分；Agent生成的示范答案不能替代用户验收。
