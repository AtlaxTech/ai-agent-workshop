# 每日整理与验收流程

所有步骤均由用户明确指令触发。Agent 不因日期变化、发现新笔记或完成上一步而自动继续。

## 开始学习时

用户对 Agent 说：

> 安排 Day N：进入导师模式，只读取路线、进度、上一日遗留项和 Day N 笔记。生成今天的 8 小时任务，不推进其他事项。

Agent 先检查前一日未通过项；最多用 45 分钟补洞，不把一天重新变成旧内容复习。安排完成后停止。

## 学习过程中

用户可以记录：

- 自己的原始理解，不要求第一次表达就正确；
- 亲自输入的代码和对输出的预测；
- 报错原文、尝试和判断；
- 对课程内容的质疑；
- 想问导师的问题。

原始材料进入 `01-输入区/Day-N/`，当天工作记录进入 `02-每日笔记/Day-N/学习记录.md`。Agent 可以解释、给更小的例子和定位提示，但不先替用户完成全部练习。

## 每日结束时

用户对 Agent 说：

> 整理 Day N：保留我的原始记录，把确认正确的内容整理成知识点；把错误理解放进纠错区；根据真实完成内容验收并更新进度。

Agent 依次完成：

1. 不删除或改写原始输入，在 `03-整理区/` 生成可追溯的整理页。
2. 区分已理解、待验证、当前错误和仍有疑问。
3. 用当天代码和实际输出核对实验是否运行。
4. 检查是否存在完整故障闭环：现象 → 假设 → 检查 → 结论 → 验证。
5. 在 `07-总结与评估/每日总结/` 记录当天总结。
6. 更新投入时间、完成度、遗留问题和次日补洞。
7. 不自动出题、复习或调整下一日计划。

## 练习题

用户说 `出题 Day N` 后，Agent 根据当天实际学习内容出 10–20 道题，覆盖概念判断、代码阅读、输出预测、错误定位和场景设计。

- 题目、用户答案、标准答案与解析保存在 `04-练习区/Day-N/`。
- 交互答题时一次只问一题，等待回答后再继续。
- 解析说明正确原因、错误思路和相关知识点。
- 错题进入 `06-复习区/错题与薄弱项.md`。

## 口述与通过标准

用户完成 3–5 分钟中文脱稿讲解，可用文字转述代替录音。

- `通过`：实验运行 + 复述清楚 + 检查题至少 80% 且能说明理由 + 故障记录完整。
- `部分通过`：实验运行，但解释或检查题不足；次日先补最多 45 分钟。
- `未通过`：只看课程、没有运行，或无法说明成功判断。

验收结果用于调整学习，不作为对外求职缺点标签。
