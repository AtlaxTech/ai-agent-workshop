# Day 1 + Day 2 — 转岗导向联合计划（2026-08-21）

## 唯一目标

为从传统 Java 开发工程师转向 Applied AI Engineer 并求职建立直接证据。课程是查缺补漏工具，不是交付目标；今天的核心产出是一个带验证、失败处理和测试的 AI 应用服务，以及能够解释其工程边界。

## 课程处理原则

- Python 基础已学过的内容允许倍速播放、跳过重复总结和案例讲解；按真实情况记录“观看未验证”或“快速通过”，不要求逐集深练。
- “学过”和“掌握”分开：课程可以算看过，但只有代码、测试、修改或解释证据才能支持掌握结论。
- Python 只学习会直接阻塞 AI 工程的部分：函数、类型提示、模块、异常、类、Pydantic、JSON、HTTP、pytest、async 基础。
- 到时间立即停止课程，不为了集数挤占项目。遇到已经熟悉的 Java 共通知识，只确认 Python 写法和差异。
- 后续每日计划默认把课程压缩为辅助输入，把主要时间留给 LLM、RAG、tool calling、Agent workflow、评测、可靠性和项目。

## 任务一：Python 课程快速扫线

- **目标**：快速通过 P17–87，识别会直接阻塞 AI 项目的 Python 差异点；若进度允许，预看 P173–174 FastAPI。
- **材料**：[黑马程序员 Python+AI 课程](https://www.bilibili.com/video/BV1sHU9BmEne) P17–87、P173–174；熟悉内容倍速并跳过重复总结。
- **动手产出**：只为暴露出的缺口写最小片段；至少验证函数与类型提示、异常、模块导入、Pydantic 模型四类写法。
- **完成判断**：真实记录最后观看分集和跳过原因；列出“不需要再学”“需要项目中巩固”“仍然陌生”三类内容。看过可以结束课程输入，不等于自动写成掌握。
- **预计时间**：2 小时，上限固定。

## 任务二：Applied AI Engineering 应用链

- **目标**：从系统角度理解一个 AI 应用，而不是孤立背 token、embedding 或框架名。
- **材料**：LLM 全景材料与本周路线；重点围绕模型调用、上下文、结构化输入输出、工具、状态、验证、日志和评测。
- **动手产出**：在 [Day 1 学习记录](../Day-1/学习记录.md) 画出“请求 → 校验 → 上下文 → 模型/工具 → 结构化输出 → 验证 → 日志/评测”链路，并标出今天项目实现和暂未实现的部分。
- **完成判断**：能解释 LLM、RAG、Agent、workflow 的边界；能说明模型有回复为什么不等于业务成功；能把 Java Web 经验映射到 AI 应用的请求、服务、外部依赖、异常和测试层。
- **预计时间**：60 分钟。

## 任务三：最小 AI 请求网关——设计与工程骨架

- **目标**：用一个求职相关项目同时学习 FastAPI、Pydantic、JSON、HTTP、模块边界和异常，而不是另做通用任务 CRUD。
- **材料**：课程 P71–87、P173–174，FastAPI/Pydantic 官方文档按需查询。
- **动手产出**：在 `05-项目区/` 创建最小 AI 请求网关，至少包含请求模型、结构化响应模型、API 路由、服务层和模型客户端接口；请求可包含 prompt、model、temperature 等最小字段。
- **完成判断**：项目 README 写明安装、运行、请求示例、预期响应和成功标准；API 层不直接塞满模型调用细节；能解释为什么要把模型客户端隔离成接口。
- **预计时间**：90 分钟。

## 任务四：模型调用、失败路径与可观察性

- **目标**：让项目具备 AI 工程而非普通 CRUD 的关键特征：外部模型依赖、超时/连接失败、输出校验和可观察结果。
- **材料**：优先使用本机 Ollama 的 OpenAI-compatible 接口；如果环境尚未就绪，则用可替换的 fake client 保持主流程可运行，并明确记录限制。
- **动手产出**：完成一次模型调用或 fake client 调用；处理至少两种失败，如非法参数、连接失败、超时或结构化输出不合法；记录请求 ID、耗时或结果状态，不记录敏感数据。
- **完成判断**：正常路径和失败路径都有实际输出；错误不会无差别变成 500；能说明哪些信息适合日志、哪些不应记录。
- **预计时间**：90 分钟。

## 任务五：确定性测试与工程判断

- **目标**：证明系统行为，而不是证明模型“碰巧回答了一段文字”。
- **材料**：pytest、FastAPI TestClient、依赖替换或 fake client。
- **动手产出**：至少 4 个测试：合法请求、Pydantic 校验失败、模型客户端失败、结构化输出失败；真实 Ollama 调用作为独立 smoke test，不作为默认单元测试依赖。
- **完成判断**：测试亲自运行并记录结果；能解释为什么单元测试应替换不稳定模型依赖，以及测试验证的是外部行为而非内部实现。
- **预计时间**：90 分钟。

## 任务六：双 Day 验收与转岗表达

- **目标**：分别保留 Day 1/Day 2 基础证据，同时把结论转化为 Applied AI Engineer 面试可表达内容。
- **材料**：[Day 1 学习记录](../Day-1/学习记录.md)与 [Day 2 学习记录](学习记录.md)。
- **动手产出**：完成两个 Day 的必须问题；做一次 5 分钟口述，主线为“我如何把 Java 服务工程经验迁移到一个可靠的 AI 请求服务”；写下现在能做什么、仍然不懂什么和实际有效时间。
- **完成判断**：基础问题能够回答；项目有运行/测试证据；至少留下一个“现象 → 假设 → 检查 → 结论 → 验证”故障闭环。未通过项如实记录，不为了完成日期放宽标准。
- **预计时间**：30 分钟核心收口；若项目提前完成，扩展到 60 分钟。
